                          📦 RIDE SERVICE (Port: 8083)
================================================================================

Purpose: Manages ride creation, searching, and lifecycle (accept, start, complete, cancel)

--------------------------------------------------------------------------------
1. MAIN APPLICATION
--------------------------------------------------------------------------------

📄 RideServiceApplication.java
   Path: /backend/ride-service/src/main/java/com/campusride/rideservice/RideServiceApplication.java
   
   - Main entry point for Ride Service
   - Starts Spring Boot application
   - Enables Eureka client for service discovery
   - Runs on port 8083

--------------------------------------------------------------------------------
2. CONTROLLERS (API Endpoints)
--------------------------------------------------------------------------------

📄 RideController.java
   Path: /backend/ride-service/src/main/java/com/campusride/rideservice/controller/RideController.java
   
   Purpose: Handles HTTP requests for ride operations
   
   Endpoints:
   - POST   /api/rides              → Create new ride
   - GET    /api/rides/{id}         → Get ride details by ID
   - POST   /api/rides/search       → Search available rides
   - PUT    /api/rides/{id}/accept  → Accept ride (for passengers)
   - PUT    /api/rides/{id}/start   → Start ride (driver marks as started)
   - PUT    /api/rides/{id}/complete → Complete ride
   - PUT    /api/rides/{id}/cancel  → Cancel ride
   - GET    /api/rides/driver/{id}  → Get all rides by driver ID
   - GET    /api/rides/passenger/{id} → Get all rides by passenger ID

--------------------------------------------------------------------------------
3. ENTITIES (Database Models)
--------------------------------------------------------------------------------

📄 Ride.java
   Path: /backend/ride-service/src/main/java/com/campusride/rideservice/entity/Ride.java
   
   Purpose: Database table model for rides
   
   Fields:
   - id: Unique ride identifier
   - driverId: ID of driver who created ride
   - passengerId: ID of passenger who accepted ride (null if not accepted)
   - type: OFFERING or REQUESTING
   - source: Starting location
   - destination: End location
   - departureTime: When ride will start
   - availableSeats: Number of seats available
   - pricePerSeat: Cost per seat in rupees
   - status: PENDING, ACCEPTED, STARTED, COMPLETED, CANCELLED
   - notes: Additional information
   - createdAt: When ride was created
   
   Business Methods:
   - acceptRide(passengerId): Changes status to ACCEPTED, sets passenger
   - startRide(): Changes status to STARTED
   - completeRide(): Changes status to COMPLETED
   - cancelRide(): Changes status to CANCELLED

--------------------------------------------------------------------------------

================================================================================
                        🔄 HOW SERVICES WORK TOGETHER
================================================================================

SCENARIO 1: Driver Creates a Ride
----------------------------------
1. Driver fills create ride form in frontend
2. Frontend → POST /api/rides (Ride Service)
3. Ride Service:
   - Validates data
   - Saves ride to database with status PENDING
   - Fetches driver's vehicle info from User Service
   - Returns RideResponse with vehicle info
4. Frontend displays success message

SCENARIO 2: Student Searches for Rides
---------------------------------------
1. Student types in search box (real-time)
2. Frontend → POST /api/rides/search (Ride Service)
3. Ride Service:
   - Filters rides where:
     * status = PENDING
     * departureTime > NOW
     * driverId ≠ current user (hide own rides)
     * source/destination matches search
   - For each ride, fetches vehicle info
   - Returns list of RideResponse
4. Frontend displays ride cards with vehicle numbers

SCENARIO 3: Student Books a Ride
---------------------------------
1. Student clicks on ride card
2. Frontend shows RideDetailsPage
3. Student clicks "Book Ride"
4. Frontend → PUT /api/rides/{id}/accept (Ride Service)
5. Ride Service:
   - Validates ride is PENDING
   - Updates ride: status = ACCEPTED, passengerId = student ID
   - Decrements availableSeats
   - Returns updated RideResponse
6. Frontend → POST /api/bookings (Booking Service)
7. Booking Service:
   - Creates booking record
   - Calculates totalPrice
   - Returns BookingResponse
8. Frontend shows booking confirmation

SCENARIO 4: Driver Starts Ride
-------------------------------
1. Driver goes to My Rides
2. Clicks on accepted ride → "Start Ride"
3. Frontend → PUT /api/rides/{id}/start (Ride Service)
4. Ride Service:
   - Validates ride status is ACCEPTED
   - Updates status to STARTED
   - Returns updated RideResponse
5. Frontend updates UI showing ride is in progress

SCENARIO 5: Driver Completes Ride
----------------------------------
1. Driver clicks "Complete Ride"
2. Frontend → PUT /api/rides/{id}/complete (Ride Service)
3. Ride Service:
   - Validates ride status is STARTED
   - Updates status to COMPLETED
   - Returns updated RideResponse
4. Frontend → GET /api/bookings/ride/{id} (Booking Service)
5. Booking Service returns all bookings for this ride
6. Booking Service marks bookings as COMPLETED
7. Frontend shows completion confirmation


================================================================================
                          📊 DATABASE TABLES
================================================================================

RIDES TABLE
-----------
id                  BIGINT (Primary Key)
driver_id           BIGINT (Foreign Key → users.id)
passenger_id        BIGINT (Foreign Key → users.id, nullable)
type                ENUM('OFFERING', 'REQUESTING')
source              VARCHAR(255)
destination         VARCHAR(255)
departure_time      DATETIME
available_seats     INT
price_per_seat      DECIMAL(10,2)
status              ENUM('PENDING', 'ACCEPTED', 'STARTED', 'COMPLETED', 'CANCELLED')
notes               TEXT
created_at          DATETIME

BOOKINGS TABLE
--------------
id                  BIGINT (Primary Key)
ride_id             BIGINT (Foreign Key → rides.id)
user_id             BIGINT (Foreign Key → users.id)
seats_booked        INT
total_price         DECIMAL(10,2)
status              ENUM('PENDING', 'CONFIRMED', 'CANCELLED', 'COMPLETED')
created_at          DATETIME
updated_at          DATETIME


================================================================================
                          🔐 SECURITY & VALIDATION
================================================================================

Ride Service:
- No authentication (relies on API Gateway)
- Validates departure time is in future
- Prevents invalid status transitions
- Filters own rides from search results

Booking Service:
- No authentication (relies on API Gateway)
- Checks seat availability before booking
- Validates ride exists via Ride Service
- Prevents double booking same ride


================================================================================
                          🚀 RUNNING THE SERVICES
================================================================================

Prerequisites:
- Java 17
- Maven
- MySQL running on localhost:3306
- Eureka Server running on port 8761

Start Ride Service:
cd backend/ride-service
mvn spring-boot:run

Start Booking Service:
cd backend/booking-service
mvn spring-boot:run

Health Check:
- Ride Service: http://localhost:8083/actuator/health
- Booking Service: http://localhost:8084/actuator/health


================================================================================
                          📝 IMPORTANT NOTES
================================================================================

1. Ride Service fetches vehicle info from User Service for display in frontend
2. Both services register with Eureka for service discovery
3. Ride Service filters past rides - only shows future rides
4. Real-time search in frontend filters results as user types
5. Vehicle numbers are displayed in ride cards (e.g., GJ01AB1234)
6. Booking Service doesn't directly modify rides - calls Ride Service API
7. All exceptions return proper JSON error responses
8. CORS is configured to allow frontend (localhost:5173) to call APIs
